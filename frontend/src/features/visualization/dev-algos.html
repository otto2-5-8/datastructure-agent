为什么换个算法还能用

step（引擎输出）→adapter（算法专属）→frame（中性帧）→renderer（通用）
  • 渲染器只认 { cells, pointers, range, caption }，不认 left/right/mid
  • 指针数量、名字、含义由算法自己定：二分是 L/R/M，冒泡是 j / j+1，线性是 cursor
  • 播放控制（createPlayback）本来就与算法无关，只认 steps 数组长度与下标

真正接一个新算法要做什么

  • 04（引擎）：按步骤契约输出轨迹（每步一个状态快照 + 该算法的语义字段）
  • 03（渲染）：加一个 xxxFrame(step) 适配器，必要时加一种 kind（数组 / 树 / 图 / 链表）
  • 02（装配）：把新算法的运行接到同一套播放控制与步骤分发上
  • 契约要泛化：现在的 step.schema.json 把 algorithm 写死成 binary-search、variables 必须含 left/right/mid

本页的诚实边界

  • 二分查找步骤 = 后端真实引擎（POST /api/algorithms/binary-search/runs），失败才用 fixtures
